# V4.0 参考包对照

对照桌面的 `ai-3d-print-workbench-v4.0-跑通版.zip` 和 `ai-3d-print-workbench-v4.0-免安装版.zip`。直接在 ZIP 内读取源码与产物清单。对照范围内共有 54 个相同的源码和文档文件，跑通版另带 5 个测试文件。业务源码一致，交付形式不同。

| 项目 | 跑通版 | 免安装版 |
|---|---|---|
| 压缩包 | 569,983 字节 | 250,736,174 字节 |
| 运行材料 | 源码、测试、数据库和 10 组模型版本 | 源码、Python 运行时与编译后的网页 |
| 几何产物 | 10 组非空 STEP、STL 和 GLB，10 个零字节 3MF | 未打包历史模型样件 |
| 切片底座 | 依赖外部 OrcaSlicer，通过进程调用 | 同样依赖外部 OrcaSlicer |
| 验收附件 | 无生成的 G-code、原生切片日志或实体设备回执 | 无生成的 G-code、原生切片日志或实体设备回执 |

## 可参考的设计

- `web/src/App.tsx` 的工作区把三维模型、参数编辑、制造检查和历史放在同一个界面，可参考它的参数确认及保存流程。其 CAD 底层包含 build123d，参数化建模之后可导出多种文件。
- `web/src/components/GcodeLayerViewer.tsx` 的 XY 刀路和分层滑块适合在派发前检查切片。本项目采纳该交互，在本机样件页上从验证过的真实 G-code 计算每层的挤出轨迹并绑定 SHA-256。
- `printer_gateway/base.py` 的设备状态与操作能力契约可作为后续适配的起点。当前 E 盘项目的只读探针保留未知、离线与连接状态来源，设备控制留到实体机型验收。

## 验收差异

| 模块 | 可从参考包核实的行为 | 后续接入的验收条件 |
|---|---|---|
| 拍照与图片 | `web/src/App.tsx` 使用一个带相机选项的图片选择器。 `api/main.py` 保存文件及哈希，几何由描述、模板和尺寸参数生成，像素未参与重建。 | 分开记录输入来源。让影像实际参与 CAD 特征提取或 Mesh 重建，标清比例和尺寸可信度。 |
| 切片 | `slice_worker/orcaslicer.py` 调用 OrcaSlicer，但机型、材料、层高、填充和支撑参数只记录在结果中，未传入切片命令。 | 固定机型、工艺和耗材预设，校验输入与切片哈希，以实际分层挤出结果复核。 |
| 原版 CLI 产物 | 原版路径寻找目录内独立 G-code 文件，未提取切片 3MF 内的刀路。 | 从实际产物提取刀路并校验，记录引擎、配置和失败状态。 |
| 局域网 | 有 OctoPrint、Moonraker 和模拟驱动。自动化用例覆盖模拟设备或固定响应。 | 真机读状态、校验目标机型与文件、明确确认、取得上传/开始/完工回执。 |
| 蓝牙与云 | 支持表将 BLE 和厂商云放在规划阶段。 | 依据指定设备的官方协议获得授权并完成下发、设备回传和控制验收。 |
| 自由建模脚本 | 本机子进程、语法检查和超时用于约束生成脚本。 | 按原需求落实文件、网络和资源隔离后开放多人使用。 |

保留两个 ZIP 原样。E 盘项目使用自己的依赖锁定、模型验证和样件产物。参考包里的账户环境、数据库和二进制运行时无需导入。
